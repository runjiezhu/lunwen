## 2. 缺口地图（Gap Map）

按"越靠近顶会审稿人关注点，越值钱"排序。

### GAP 1 ★★★★★ —— 核心矛盾：LLM 的价值主张从未被真正检验

**问题**：在 highway-v0 上，LLM 能看到的输入是 5 维运动学向量（位置、速度、朝向）。人类专家拿到同样的信息，**手工就能写出** `right_lane_reward`、`high_speed_reward`、`collision_reward`。也就是说：**LLM 相对于手工专家，提供的信息增量接近于零。**

这意味着 LLM-PPO Driver 实际上只证明了"加了一组合理奖励项比不加要好"——**这不需要 LLM 也能做到。** 它的实验无法支持"LLM 带来增量"这个主张。

**创新点 1（主线）**：在**像素/BEV 观测**的真实感环境（CARLA / NAVSIM / MetaDrive）下，论证 LLM 语义先验提供了**手工奖励函数无法编码**的信息增量，并设计对照实验隔离出这部分增量：
- 对照组 A：手工 shaping（专家规则）
- 对照组 B：LLM shaping
- 对照组 C：无 shaping
- 关键：在 highway-v0 上 A ≈ B，在 CARLA/NavSim 上 B ≫ A
- **这个"差距是环境逼出来的"的结果，本身就是一个有价值的科学发现**

### GAP 2 ★★★★★ —— 奖励塑形的理论性质缺失（护城河）

**问题**：LLM 生成的塑形项是任意形式的加分（"保持车道 +1""安全距离 +1"）。按 Ng, Harada & Russell (1999)，只有 potential-based 形式 $r' = r + \gamma\Phi(s')-\Phi(s)$ 才保证**最优策略不变**。任意塑形会**改变最优策略**，导致：
1. 策略可能只是在迎合 LLM 评分函数，而非真的更安全
2. baseline（无塑形）与本方法（塑形）**优化的不是同一目标**，比较不公平
3. 审稿人必问："你怎么保证 LLM 的奖励没把策略带偏？"

**创新点 2（护城河）**：把 LLM 塑形项**结构化约束为 potential-based 形式**，或给出等效的"退场论证"：
- 训练早期：$\Phi$ 密集引导
- 训练后期：$\Phi \to 0$，奖励退化为原始稀疏安全 + 效率奖励
- **可证明**：退火路径下最终策略与纯原始奖励的最优策略一致
- 附加分析：**移除塑形项重评估**（训练完把 $\Phi$ 关掉再测），报"性能保持率"——直接回应 reward hacking 质疑

LLM-PPO Driver 的摘要完全没有触及这一层。**这是你防守最稳、对方最空的位置。**

### GAP 3 ★★★★ —— 时间维度：curriculum 退场机制

**问题**：LLM-PPO Driver 是**静态**塑形——一套奖励项从头用到尾。但稠密的引导奖励在训练后期会**阻碍**真稀疏安全目标的优化（策略被"喂饱"了，不再探索稀有失败事件）。

**创新点 3**：把"退场"做成**可证明的 curriculum 机制**而非工程 trick：
- 塑形权重 $\lambda_{\text{shape}}(t)$ 的退火曲线
- 与固定塑形、线性退火、指数退火的对照
- 关键指标：退火后的**样本效率**反而更好（因为后期回到了真稀疏信号）

**同时注意工程坑**：中途改奖励函数会破坏 PPO 的数据复用假设（旧数据里的 $\hat{A}_t$ 是用旧奖励算的），且价值网络的标度不再匹配。**必须把奖励切换放在 iteration 边界并重校准价值网络。** 这一条写进论文是实打实的加分项。

### GAP 4 ★★★★ —— LLM 输出的可靠性从未被处理

**问题**：LLM 输出是随机的、有幻觉的、会漂移的。同一场景两次调用可能给出不同奖励。LLM-PPO Driver 假设"LLM 提供 structured prior knowledge"——**但没处理这个 prior 本身不可靠**。

**创新点 4（不确定性感知塑形）**：
- 用 LLM ensemble（多次采样）估计每个子目标奖励的**置信区间**
- 塑形项取**保守下界**（悲观塑形），或按置信度加权
- 引入"塑形项的方差"作为可解释的诊断指标：什么场景下 LLM 自己也不确定
- 附加产出：**"LLM 何时不该被信任"的场景分类**，这本身可发表

### GAP 5 ★★★ —— 评测协议可以成为贡献

**问题**：这类工作的通病是单环境、种子少、无显著性检验、无泛化测试。

**创新点 5**：提出一个**去偏评测协议**作为方法论贡献（而不只是"多做了实验"）：
1. **塑形移除重评估**（训练后关掉 $\Phi$ 再测）→ 排除 reward hacking
2. **跨环境泛化**（训练 env → 测试 env，场景布局/交通密度/天光变化）
3. **多种子 + 配对检验**（同一 seed 配对，跑 paired t-test / Wilcoxon）
4. **塑形必要性对照**（LLM 塑形 vs 手工塑形 vs 随机塑形）→ 随机塑形是必做项！**如果随机权重塑形也有同样增益，那 LLM 什么都没带来**——这个对照能直接杀死或救活"LLM 有用"这个主张
5. **塑形项的信息量分析**（LLM 塑形项与手工项的 Spearman 相关性）→ 量化"LLM 到底说了什么新东西"

**第 4 条"随机塑形对照"是杀手锏式的实验设计。** 6 页的会议论文不会有这个，但它能一次性把"LLM 真的有用"这件事钉死或钉死对方的说法。

### GAP 6 ★★★ —— 与非 PPO 路线（GRPO / DPO）的对照缺失

**问题**：整个 LLM+RL 赛道大量工作用 GRPO/DPO（无需 critic），但 AD 连续动作空间里 critic 仍必要。这件事没人在自动驾驶里系统论证过。

**创新点 6（负面结果 + 解释型贡献）**：
- 在同一环境下实现 GRPO 版与 PPO 版
- 论证连续控制下 critic 的必要性（GRPO 的组内基线方差问题）
- **"负面结果 + 深度解释"是顶会接受的贡献形式**，只要解释得透彻

## 3. 推荐的创新点组合

### 主线（必做，2 个点）

| 编号 | 创新点 | 论文卖点 |
|---|---|---|
| **A** | **真实感环境 + LLM 信息增量隔离实验** | "我们证明了 LLM 塑形真正有价值的条件：观测语义不可手工编码时" |
| **B** | **potential-based 塑形 + 退场 curriculum + 塑形移除重评估** | "我们给出了 LLM 塑形不影响最优策略的理论保证与实证验证" |

A 和 B 合起来构成一个完整故事：**"LLM 塑形在真实感场景下确实有增量（B 保证这个增量是真的安全而非 reward hacking）"**。

### 辅线（选 1 个）

| 编号 | 创新点 | 风险 |
|---|---|---|
| **C** | 不确定性感知塑形（LLM ensemble + 保守下界） | 中等，需要多次 LLM 调用成本论证 |
| **D** | 去偏评测协议（随机塑形对照、跨环境泛化、显著性检验）作为方法论贡献 | 低，纯工作量，但顶会审稿人很认严谨 |
| **E** | GRPO vs PPO 在连续 AD 动作空间的对照 | 中等，需要实现 GRPO 变体 |

**推荐组合：A + B + D。** D 成本低、收益稳（直接决定你能不能过审），A+B 撑起方法论贡献。

### 完整贡献列表写法（可直接抄进论文）

```
1. 我们识别出 LLM 引导的 reward shaping 在自动驾驶 RL 中缺乏信息增量的
   严格验证，并设计隔离实验证明：仅当观测语义无法被专家手工编码时
   （像素/BEV 而非运动学向量），LLM 先验才产生超越手工塑形的增益。
2. 我们提出 potential-based 约束的 LLM 塑形框架与可证明退场的
   curriculum 机制，保证最优策略不变，并通过"塑形移除重评估"
   实证排除 reward hacking。
3. 我们提出一套去偏评测协议（随机塑形对照 + 跨环境泛化 + 配对显著性
   检验 + 信息量分析），作为 LLM 辅助 RL 类工作的社区评测标准。
```

## 5. 风险与前置检查

| 风险 | 说明 | 缓解 |
|---|---|---|
| **"LLM 塑形 vs 随机塑形"没有差距** | 如果随机权重的塑形也有同样增益，整个方向就死了 | 先花 2 天做这个 pilot：在 highway-v0 + CARLA 各跑一次"LLM 塑形 / 手工塑形 / 随机塑形"。**这是 go/no-go 实验，必须最先做** |
| CARLA 训练成本 | 图像观测 + 连续动作，PPO 采样开销大 | 用 NAVSIM（纯轨迹回放，评测向）做主战场，CARLA 只做 1–2 个场景的闭环验证；或 MetaDrive（比 CARLA 快很多） |
| LLM API 成本与延迟 | curriculum 每步都要调 LLM 不现实 | LLM **只在 episode 级**或每 K 步调用一次，输出"本回合的子目标配置"而非逐帧奖励；用本地开源模型（Qwen/Llama）控成本 |
| 顶会选错 | 你的方法是 RL+LLM+AD 交叉 | 首选 CoRL / ICRA / IROS（embodied 侧）、IEEE T-ITS / T-IV（期刊侧）；CVPR/NeurIPS 需要更强的视觉或学习理论成分 |
